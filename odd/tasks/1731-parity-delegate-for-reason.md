## Specs

- S1 Writer by reason: a writer is delegated only for a named reason (parallel units launched together, or the context backstop); never for size, file count, or a price ratio. Without a reason the parent works inline with its logbook.
- S2 Parallel writers (user, verbatim L80): "Sí, pero que sean repositorios diferentes, por ahí el WordTree está bueno, porque por ahí en ese otro repositorio hay alguien que ya está trabajando, ¿se entiende? Entonces siempre tiene que ser basado en main o algo por el estilo. Y lo que es en local, lo que sea más sencillo consuma menos tokens." Rule: work in another repository goes in a fresh worktree based on that repository's main; parallel units in the same local repository run in the same tree with declared disjoint edit surfaces, the parent owns git, no repo-wide formatters/generators/installs, shared files have one owner or are done by the parent at the end, the parent checks each writer's diff against its surface before accepting, and one seam check runs at the end; units that need the same file use isolated worktrees. This replaces "single writer unless isolated worktrees".
- S3 Risk line: every code change closes with `Risk: item N (reason)` or `Risk: none`; high-risk item 1 is about changing or deleting existing stored data (not saving new records); item 3 is about changing or removing contracts others already consume (not adding a flag or command; requested changes are not high risk by themselves; unrequested breaks in shared code are). Before writing `Risk: none`, check whether the diff changes code that existing behavior the request did not mention also uses.
- S4 No self-pause: hedged wording is not a stop; a tracked task ends pending only with the user's explicit stop or one "Needs your decision" result naming the open blockers or missing proof.
- S5 Explore only for a map the parent needs to decide or route; never to read files the parent will read anyway before writing inline.
- S6 Tests: one RED test per requested rule covering the cases that rule names; PRESERVE: one test per existing command or option the change touches proving its previous behavior still holds (an existing behavior counts as touched when it shares the changed code); no other cases (no padding); update help text and docs for any changed command, option, or message.
- S7 Verify (where a verify agent exists): spec-derived probes on the first launch inside a scratch copy created with mktemp under the system temp dir, never inside the workspace, leaving no new file in the workspace; severity: a blocker is a change-caused defect or unmet spec item reproduced with realistic input, reproduced at the baseline first; baseline behavior not asked to change and out-of-domain values are advisories; silently ignoring an explicit option with success and unrequested changes to existing output are blockers.
- S8 Verification timing and bounds: one end-of-feature verify when the same model wrote several deliveries inline; per-unit verify on real high risk and always on smaller-model code; one correction batch for all blockers and one recheck limited to them; a second correction only when the same blocker still fails; worker self-review gets the same bound and then reports partial.
- S9 Do not port Pi-runtime-only items: json single-shot handling, nan provider in children, task ids in results, runtime-enforced surface admission, price-ratio library, background policy placeholder, Node-specific scratch details.
